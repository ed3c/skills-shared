# 待人裁的一項：bettor-arena 的指針契約

`bettor-arena/scripts/gates/check_skill_pointers.py` 要求 `.claude/skills/<name>` 的
**完整解析路徑**落在 `.agents/skills/` 或 `kb-ingest/skill` 之內。共用 checkout 住在
`~/.agents/skills-shared/`，在 repo 外，所以每一條都被判 `ESCAPED-LINK`。

**這道閘在本次動工前就已經是紅的**——上一輪遷移把指針指到 repo 外，而那次的 commit 沒觸發到它。
現在 `.skill-bindings/` 的提交撞上同一道閘，才顯形。

三條路，各自的代價：

| 選項 | 做什麼 | 代價 |
|---|---|---|
| 放寬閘 | `_resolves_inside` 只驗**第一跳**是 `.agents/skills`，不追到底 | 改一支閘＋它的 selftest；契約語意仍是「`.claude/` 零內容、一律讓位給 `.agents/skills`」 |
| 改契約 | ARCHITECTURE.md 明列共用 checkout 為第三個合法 content home | 閘與文件都要動；把「內容 SSOT 在 repo 內」這條寫成有例外 |
| 退出共用 | bettor-arena 保留自己的副本 | 影蓋回來；同一修法又會在這裡被重覆發現一次 |

我沒有動這支閘：改別的 repo 已宣告的拓撲契約該是人裁，且你明說了這次不做閘門工作。
在裁決前，bettor-arena 的 `.skill-bindings/` 與 `ARCHITECTURE.md` 槽位登記留在工作樹未提交。
