# AGENTS.md — procedural-shadow-runtime

## Purpose

This directory owns reusable runtime admission, receipt closure, executable Agent Architecture assessment, and quantitative abstraction-promotion contracts. It remains narrower than `../spatial-loop-systems-engineering`.

## Authority

- `SKILL.md` defines runtime procedure and composition.
- `references/agent-architecture-rubric.json` is the atomic five-dimension scoring authority.
- `references/agent-architecture-eval-receipt.schema.json` defines executable architecture evidence.
- `scripts/agent_architecture_common.py` is the shared score/contradiction implementation.
- `scripts/check_agent_architecture_eval.py` is the standalone 100-point gate.
- `references/meta-abstraction-eval-standard.md` defines four-plane promotion rules.
- `scripts/check_meta_abstraction_eval.py` is the meta eligibility gate.
- `modules/` owns worked task families and adapters only.
- `tests/` owns positive, Vibe, unsafe, mutation, and input controls.

## Composition rules

1. The universal rubric contains concepts and evidence contracts, not consumer paths, provider credentials, business thresholds, or live runtime claims.
2. Do not accept manually entered `0..5` dimension values as architecture evidence.
3. Every positive criterion and Vibe signal must have one stable ID and a terminal evidence state.
4. `VERIFIED` and `NOT_DETECTED` require exact-subject `STATIC_ASSERTION`, `RUNTIME_PROBE`, `TRACE_ASSERTION`, or `NEGATIVE_CONTROL` evidence.
5. Prose, model self-report, README claims, and unbound screenshots do not earn points.
6. A detected Vibe signal contradicts its mapped controls. Do not mark both sides true.
7. Non-idempotent high-risk writes or model-owned high-risk authority impose the declared safety ceiling; do not average them away.
8. Shadow workers are read-only. They may propose capsules, probes, assertions, scores, and blockers, but not mutate the target runtime.
9. Retrieved Skills cannot widen tools, credentials, network, repository scope, provider scope, or data egress.
10. Keep e-commerce constants and executable fixtures under `modules/ecommerce-dispute/`; do not copy USD 500 or its tool topology into the core rubric.
11. Candidate adapters execute only inside the host-provided sandbox.
12. Semantic judges may score non-hard quality but cannot override deterministic safety failures.
13. Meta promotion remains one level at a time and only produces machine eligibility for Human Admit.
14. Live provider, production trace, model-training membership, and causal-uplift states remain `NOT_EXERCISED` without exact receipts.

## Change protocol

Any change to a criterion, Vibe signal, mapping, weight, evidence mode, score ceiling, schema, or checker must:

1. version the affected contract when compatibility changes;
2. update the source inventory and nearest README;
3. add a mutation or negative control that fails under the old incorrect behavior;
4. run all deterministic controls;
5. preserve checker exits:

```text
0  structurally and semantically closed
2  semantic/assertion refusal
64 absent or malformed input
```

Do not weaken hard gates to make a fixture pass. Do not represent static fixtures as live runtime or production evidence.
