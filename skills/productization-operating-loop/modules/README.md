# Modules

Domain instances, loaded only when their trigger matches. A module is never
passive context: if the run does not need a concrete consumer, writer or
Human-admission surface bound, no module is read.

| Module | Trigger |
|---|---|
| [`domain-profile.md`](domain-profile.md) | a concrete consumer repository, program-instance identity, lease path, writer or Human-admission authority must be bound before a stage prompt in [`../prompts/README.md`](../prompts/README.md) can be dispatched |

A module may narrow this Skill's contract — add evidence, strengthen a
constraint, reduce authority — and may not do the reverse. It may not
override the twelve-lane vocabulary, the ten-rung ladder, the state machine
or the hard laws in [`../SKILL.md`](../SKILL.md). Presence of a consumer
repository is not a trigger by itself; a frozen binding need recorded at
`CONTROL_AND_AUTHORITY_BOUND` (stage 0) is.

No module here may name a specific external consumer, carrier or repository.
`domain-profile.md` states what a consumer must supply and in what shape; the
supplied values themselves live in that consumer's own repository, never in
this portable core.
