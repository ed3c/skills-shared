# SDLC planning domain profile

Historical host/model/consumer-specific planning details remain recoverable from pre-refactor blob `0ee1ad83d34558f2182a8a3467610f663dcb804f`.

## Trigger
Load when a concrete repository planning layout, model/actor mapping, downstream family catalog, host prompt carrier, or consumer delivery convention must be bound.

## Non-trigger
Do not load for generic task classification, capability matching, invariant extraction, dependency slicing, interface planning, validation design, or handoff.

## Assumptions
The requested change can be decomposed into verifiable units with explicit dependencies, owners, interfaces, and acceptance criteria.

## Specialization inventory
Repository plan directories, named actor/provider mappings, host prompt locations, consumer family catalogs, and project-specific output routes belong here.

## Evidence ceiling
A generated plan is not implementation proof; only the owning assertions on the exact implementation subject can establish completion.

## Fallback
If a specialized planning carrier is absent, emit the portable task DAG, interfaces, risks, validation plan, and handoff packet directly.

## Forbidden overrides
This module may not override `CORE-LAW-001` through `CORE-LAW-005`, fabricate dependencies, weaken acceptance criteria, or widen provider/secret/merge authority.
