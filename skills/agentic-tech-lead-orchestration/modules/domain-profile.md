# Agentic Tech Lead capability profile

Historical product/tool-specific orchestration detail remains recoverable from pre-refactor blob `a01f53592cda98f61b413b4467afa96356fb4ef7`.

## Trigger
Load when concrete code-intelligence providers, symbol/index adapters, structural parsers, bounded executor tools, vector projections, scheduler/runtime implementations, or consumer repository integrations must be bound.

## Non-trigger
Do not load for generic task-contract compilation, DAG construction, dependency validation, path/resource leasing, worker admission, tournament selection, convergence, or stacked handoff.

## Assumptions
The orchestration problem can be expressed as typed task packets with explicit inputs, outputs, dependencies, owners, budgets, evidence oracles, and convergence rules before choosing tools.

## Specialization inventory
Semantic search/index adapters, compiler-grade semantic indexes, structural parsers, symbol/executor providers, optional vector projections, runtime scheduler bindings, and repository-specific commands belong here.

## Evidence ceiling
A provider hit, parsed graph, symbol index, vector retrieval, or worker self-report is candidate evidence only. Exact source readback and owning assertions remain higher authority.

## Fallback
When optional intelligence/execution providers are absent, fall back to direct source reads, version-control search, compiler/language-service output, deterministic tests, and bounded single-worker execution while preserving unsupported lanes explicitly.

## Forbidden overrides
This module may not override `CORE-LAW-001` through `CORE-LAW-005`, fabricate DAG dependencies, accept overlapping writers, promote provider output without readback, suppress failed workers/dissent, or widen provider/secret/merge authority.
