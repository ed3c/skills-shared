# Domain instances

`SKILL.md` owns only the runtime-supported cross-domain procedure. Load the matching section only after the claim inventory identifies the physical boundary. These are worked instances and therefore remain outside the core.

## Interactive rendering and navigation

A rendering/navigation claim binds driver and engine versions, action-plan digest, allowed origins, final assertions, page and event budgets, persisted structure/accessibility/visual/download evidence, and cleanup.

```text
loopback fixture starts
→ real engine process launches
→ action plan reaches state and side-effect paths
→ final assertions run
→ origin-denial probe records the attempted request
→ raw receipt survives a failed path
→ artifact digests are verified after publication
```

This proves only the exercised vertical slice. It does not prove hostile-code isolation, arbitrary public-site compatibility, semantic planning, or production credentials.

## Process or sandbox isolation

A sandbox claim binds the actual substrate and exercises both an admitted operation and a forbidden operation under the same launched instance.

```text
content-addressed image launches
→ bounded writable area accepts one write
→ outbound operation is attempted and denied with the expected failure class
→ immutable-root write is attempted and denied with the expected failure class
→ limits, identity and teardown metadata persist
```

A generic container cannot be relabeled as a named isolation product without that product's own receipt.

## Mutable remote input

```text
mutable locator received
→ resolver reads the remote authority
→ immutable revision returned
→ exact entrypoint fetched at that revision
→ content and provenance digests persisted
→ evaluation references only the immutable subject
```

A cached response or local copy does not prove the mutable remote currently resolves to the same subject.

## Attached or virtual device

Device evidence climbs through distinct levels and cannot skip them.

```text
compile contract
→ trusted runner bridge
→ scripted bridge command
→ virtual device execution
→ physical device execution
```

Each level binds identity, operating-system version, application identity, permissions, lifecycle transitions, logs, screenshots, and cleanup.

## Signing and public evidence

Separate cryptographic integrity from identity and public witnessing.

```text
artifact digest computed
→ statement binds exact artifact and subject
→ signature verified against a trust policy
→ inclusion receipt verified against a checkpoint
→ issuer and witness identities classified honestly
```

An ephemeral local key can prove the local signing and verification path. It does not establish workload identity, keyless issuance, or an independently witnessed public log.

## Observed repository trace

The external receipt in `evals/contract.json` records one exact-head audit run. It reached a real rendering engine, public remote ingestion, a hardened generic container, content-addressed evidence, and a downloaded publication packet.

The trace exposed five defects that static review or the first green state did not establish:

1. the compiled runner transport and packaged console entrypoint disagreed;
2. optional integration tests used a stale kernel interface;
3. the denial test admitted the origin it expected to deny;
4. failure normalization discarded a trusted denied-operation observation when positive artifacts were incomplete;
5. the first successful publication omitted nested hidden evidence.

This trace supports the fixture families and first-green publication readback. It does not isolate one model, one source skill, or one prompt clause. Repeated held-out physical runs remain required for model-behavior claims.
