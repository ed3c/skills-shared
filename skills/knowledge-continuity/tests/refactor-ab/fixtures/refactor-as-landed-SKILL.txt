# Skill: knowledge-continuity — 消除文件的知識斷點

> **Role**：對一份**給人讀的**文件，找出並修掉「讀者必須自己補知識才能繼續」的地方。
>   它不改善文筆，也不判斷結論對不對——它只保證**因果鏈在文件內部是完整的**。
> **結構**：SKILL.md ＝ 確定性程序 ＋ 人判斷準則 ＋ Gotchas；
>   四條可機械檢查的規則在 [`scripts/check_knowledge_continuity.py`](scripts/check_knowledge_continuity.py)。
> **No Prose Husk 錨**：規則有真實腳本與正負控（[`tests/run-all.sh`](tests/run-all.sh)），
>   而且每條都在真實文件上量過命中率（見 [`evals.json`](evals.json) 的 `field_evidence`）。

## 什麼是「知識斷點」

讀者讀到某一句，**必須動用文件沒有提供的知識才能繼續**。四種常見形態：

| 形態 | 讀者的實際體驗 | 規則 |
|---|---|---|
| 記憶式引用 | 「`NEG-101` 是什麼？我要去哪裡查？」 | KC-01 |
| 章節錯引 | 照著跳到「§7」，發現不是講這個，開始懷疑整份文件 | KC-02 |
| 約數 | 「約 14 列」——那到底是哪 14 列？我怎麼知道有沒有漏？ | KC-03 |
| 知識外包 | 「沿用 §5，不在此複製」——被迫中斷閱讀，回來忘了讀到哪 | KC-04 |
| 兩跳才到證據 | 「現況是 X（詳見 §11）」——跳過去發現那節又指向附錄，第二跳就放棄了 | KC-05 |

**判準只有一條**：一個只讀這份文件、沒讀過其他文件的人，能不能不中斷地讀完並理解因果。

## 🚩 STOP — 你在合理化（違反即停）

| 念頭 | 現實 |
|---|---|
| 「這個縮寫團隊都知道，不用解釋」 | ❌ 文件的讀者包含三個月後的你，以及接手的人。「團隊都知道」是最常見的知識斷點藉口 |
| 「我在開頭定義過了，後面直接用就好」 | ⚠️ 長文件是被跳讀的。定義過的代號可以直接用，但**定義必須在文件內、且可被找到**（表格首欄或標題）——這正是 KC-01 的判準 |
| 「詳細內容在另一份，這裡指過去比較不重複」 | ❌ 指過去可以，但**原地必須留一句話摘要**。讀者不必離開才叫連續 |
| 「checker 全綠了，這份文件沒問題」 | ❌ 四條規則只檢查**引用的形狀**，不檢查**說明是否足夠**。全綠只代表沒有機械斷點，人還是要讀（見 §4） |
| 「約數比較誠實，我不確定精確值」 | ❌ 不確定就去數。數不出來就不要宣稱有這個數，改成描述性語句 |

## 確定性程序

### 1. 先量，不要先改

```bash
python3 .agents/skills/knowledge-continuity/scripts/check_knowledge_continuity.py <file.md>
```

輸出每條規則的斷點數與行號。**先記下總數**——這是這輪的起點，也是之後判斷有沒有改好的唯一客觀依據。

### 2. 依規則修，每修一條就重跑

| 規則 | 修法 |
|---|---|
| KC-01 | 在同一段落內補上真實檔名；或在文件開頭建一張「本文引用的文件」表，把代號放在**表格首欄**並附檔名 |
| KC-02 | 修正章節號。若被指的章節根本不存在，代表內容缺了，補內容而不是刪引用 |
| KC-03 | 去數。數完寫實際數字，並在旁邊說明怎麼數的（例如「16 列 ＝ 18 行減表頭與分隔線」） |
| KC-04 | 原地補一句話摘要，再指過去。摘要要能讓讀者**不點進去也能繼續讀** |
| KC-05 | 把實碼錨點搬到提出主張的同一段。若證據在附錄，原地就貼出關鍵的三五行，再附代號讓人看全文 |

### 3. 人判斷的四件事（腳本做不到，見 §4）

### 4. 收斂條件

```text
   機械層：checker 四條全綠（exit 0）
       ＋
   人判斷層：§4 的四個問題都能回答「是」
       ＝ 收斂
```

**只有機械層綠不算收斂。** 腳本檢查形狀，人檢查是否真的說得通。

## §4 人判斷的四件事

腳本無法檢查以下四項，但它們是知識斷點最嚴重的形態。**每一輪都要人親自回答**：

1. **圖是不是從輸入開始畫的？**
   一張從「結論」起跳的圖（例如直接畫三個決策分支，卻沒畫證據從哪來），
   讀者無法判斷為什麼會走到那個分支。圖必須包含：輸入 → 判斷條件 → 分支 → 結果。

2. **圖用到的符號有沒有解釋過？**
   `★ ◇ ⚠ ✗ ?` 這類記號讀者只能猜。整份文件共用一張符號表，
   放在最前面；每張圖不必重複標，但**整份不能一次都沒有**。
   實例：本 skill 用自己的規則掃一份文件時，機械層全綠，
   人判斷層才發現它全篇用 `★ ◇ ⚠` 卻圖例數為 0。

3. **未裁決的事有沒有被畫成已裁決？**
   把還沒拍板的方案畫進架構圖，讀者會以為它定案了。未決的事要有獨立的「待裁決」段落，
   並且**不得出現在架構圖與決策表中**。
   實例：同一批文件裡，一份把 PIN 明確標成「待裁決」，隔壁那份卻在圖上畫成
   `★ PIN 真的驗`——同一個人、同一天、隔壁檔案就不一致了。
   這種矛盾**跨檔案才看得出來**，逐檔檢查抓不到。

4. **有沒有過度宣稱？**
   「檢查全綠 = 安全」「數字沒變 = 文件還新鮮」這類推論通常有隱藏前提。
   每個「因此」都要能回答：這個推論的前提是什麼？前提不成立時會怎樣？

5. **索引跳轉會不會把讀者送到另一個索引？**
   同一個代號常常在摘要表與真正定義它的那一節同時出現。跳轉必須落在**來源**——
   落在摘要列等於把人送到目錄。份量排序：標題 > 條列 > 表格列，
   且份量高的勝出、與文件順序無關。

6. **一個沒讀過前置文件的人，讀得完嗎？**
   最後從頭讀一遍，每遇到一個名詞就問「文件在這之前解釋過嗎」。
   這條沒有捷徑，也沒有腳本能代勞。

## 接小迴圈

本 skill 的形狀就是一個小迴圈：**量 → 改 → 重量**，直到機械層歸零、人判斷層全過。

```text
   ┌──────────────────────────────────────────────┐
   │  1. checker 量出斷點數 N                      │
   │  2. 依 §2 的對照表修                          │
   │  3. 重跑 checker                              │
   │     N 沒降 → 修錯地方了，回第 2 步            │
   │     N 降到 0 → 進第 4 步                      │
   │  4. 人回答 §4 的四個問題                      │
   │     有任一個「否」→ 補內容，回第 1 步          │
   │     全部「是」→ 收斂                          │
   └──────────────────────────────────────────────┘
```

**為什麼要有第 3 步的「N 沒降」分支**：修文字很容易改到別處而沒動到真正的斷點。
數字不降就是沒修對，這比自己讀一遍可靠。

**與 wiki 收斂迴圈的關係**：若該文件同時要進 wiki，本迴圈跑在 wiki 收斂**之前**——
先讓文件對人可讀，再談對機器可索引。順序反過來會得到一份索引良好但沒人讀得懂的東西。

## Gotchas

- **代號寫在表格首欄就算已定義**。這是 KC-01 的判準，也是最省力的修法：
  與其在每段補檔名，不如在開頭建一張引用表。腳本認得表格首欄與含檔名的表格列。
- **圖與程式碼區塊內的代號不算引用**。`◇ §7 分支` 出現在 ASCII 圖裡是標籤，不是引用，
  腳本會跳過。不要為了讓圖「合規」而把圖改得更難讀。
- **本文自己章節的 `§N` 不算斷點**。讀者捲動即可。只有指向文件外部的代號才需要落地。
- **KC-03 只在計數語境開火**（`約 14 列`／`~10 條`）。一般的「大約」不會被誤判。
- **有些規則被寫了又拿掉**，理由記在腳本的 `REJECTED_RULES`，用
  `--rejected` 可看。**不要重新推導它們**——它們在真實文字上會誤報，
  而會誤報的閘門比沒有閘門更糟：人會學會忽略它。
- **ISO 日期不是文件代號**。`2026-08-06` 裡的 `08-06` 形狀和 `08-05` 這種文件代號
  一模一樣。KC-01 曾因此在每份文件的 frontmatter 上誤報，修法是排除前面接 `YYYY-` 的情形。
- **一份「解釋什麼是壞引用」的文件必須能引用壞例子**。引號與反引號裡的內容是
  **被展示的**不是**被使用的**，比對前要先剝掉——這條是拿本 skill 掃自己的
  SKILL.md 才發現的。
- **規則太寬時要收窄，不要加特例**。KC-05 第一版抓所有「現況」句，在
  「目前沒有裁決」（講決策）與「實測會擋下」（講測試）上誤報。需要一堆特例
  才不誤報，就是規則還沒成熟——收窄成單一形狀（現況主張＋指向另一節＋同段無實碼）後才穩定。
