# Four-repository routing example

This is a domain instance of `knowledge-continuity`; it is not a universal Skill law.

## Scenario

An Agent must determine how a browser-assisted research workflow becomes an executable consumer capability.

## Route

```text
skills-shared
  find the selected procedural Skill and its method contract
        |
        v
runtime-env
  find the secret-free browser/runtime profile, workload, and policy requirements
        |
        v
the host repo
  find the selected module closure, MCP exposure policy, proof/control/mutation, and origin contract
        |
        v
agent-shield-monorepo
  find the product workflow binding, provider state, terminal issue, and live receipt
```

At each repository:

1. read `AGENTS.md`;
2. read `CONTEXT.md` and `ARCHITECTURE.md`;
3. use `docs/INDEX.md`;
4. read the nearest directory README;
5. stop at the machine authority;
6. read the traceability/evidence route.

## Why the separation matters

- The shared Skill explains how to verify and route; it does not store the consumer's browser profile or account.
- `runtime-env` names variables and policy but not secret values.
- The host repo proves composition and public execution surfaces but does not own the product implementation.
- Agent Shield owns the domain workflow and provider-specific outcome.

A declaration in an upstream plane cannot proxy a downstream live receipt.
