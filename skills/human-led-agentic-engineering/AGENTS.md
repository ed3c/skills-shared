## Read order

For work in this directory:

1. Read this file.
2. Read `README.md` for topology, State Machine, DAG, data flow and current issue boundaries.
3. Read `SKILL.md` for portable laws and stop conditions.
4. Read only the references/modules/scripts selected by the current transition.
5. Read the composing canonical Skills before changing their owned contracts:
   - `../agentic-tech-lead-orchestration/`
   - `../procedural-shadow-runtime/`
   - `../spatial-loop-systems-engineering/`
   - `../git-town-stacked-pr-worker/`

## Authority

```text
Human / legal / permission boundary
→ exact design/task/capability contract
→ deterministic/native/domain verification
→ provider evidence
→ durable architecture/context
→ Agent prose
```

Provider availability, model consensus, review prose, dashboard metrics, issue state, or a green documentation check cannot create Human Admit or correctness PASS.

## Ownership boundaries

This Skill owns:

- Human design-admission workflow;
- independent Design Adversary role separation;
- provider-neutral intent/review/observability/workspace/session ports;
- commit/branch review reconciliation semantics;
- living-context persistence routing;
- Kenn-derived closure map at the procedural level.

This Skill does **not** own:

- concrete Worker scheduling, leases or Local Handoff semantics;
- Shadow runtime implementation;
- architecture-delta evaluator implementation;
- Git Town branch/worktree mechanics;
- provider credentials, local databases or sessions;
- consumer issue/PR identities;
- merge, release, visibility or production authority.

## Change protocol

When changing a state, interface, provider boundary, evidence ceiling or Stack decomposition:

1. update `SKILL.md` if portable behavior changes;
2. update `README.md` if topology/State Machine/DAG/data flow changes;
3. update the exact machine contract/checker if a machine transition changes;
4. update root routing/traceability in a separate convergence/index slice when appropriate;
5. preserve open issue state for anything not executed and verified on an exact subject.

## Stop conditions

Stop on absent Human design admission for material architecture, overlapping ownership with another shared Skill, provider source-license ambiguity, stale/wrong-subject evidence, provider output being promoted to correctness authority, suppressed Shadow dissent, or any irreversible delivery action without its owning Human/trusted-policy admission.
